**结论先行**：
1. 你选的 OpenMU 是**服务端**，本身不含游戏素材，这是正常的——配套开源客户端是 **`sven-n/MuMain`**，游戏资源（约 447MB）由该仓库的 Release 单独分发（`data-<id>` 标签）。两个仓库配合即为完整游戏。
2. 客户端已内置高帧率支持（VSync 无上限/帧率限制解耦游戏逻辑）、分辨率切换、跨三平台官方构建、成熟翻译系统——**大量工作是"补齐与增强"，不是从零发明**。
3. 手柄是完全没有的，需要新建子系统，是本计划最重的模块（M4）。
4. 数值全部在服务端数据库里，通过网页管理面板即可改，**不需要改代码、不需要重新编译**。

## 1. 项目与仓库现状（必读背景）

### 1.1 两个核心仓库

| 仓库 | 角色 | 技术栈 | 许可证 |
|---|---|---|---|
| `https://github.com/MUnique/OpenMU` | **服务端**（连接服/游戏服/聊天服/登录服/管理面板） | C# / .NET / EF Core / PostgreSQL / Blazor Server 管理面板 | MIT |
| `https://github.com/sven-n/MuMain` | **开源客户端**（OpenMU 官方 README 指定的长期配套客户端） | C++ / CMake / SDL3（SDL GPU 渲染：Windows=D3D12、Linux=Vulkan、macOS=Metal）+ .NET 10 Native AOT 网络库 | 见仓库 |

- OpenMU 主打 **Season 6 Episode 3（ENG 协议）**；MuMain 由 Season 5.2 客户端源码（LouisEmulator/Main5.2）清理重构而来，目标即对齐 S6E3，并扩展了协议（伤害/经验突破 16 位等）。**两者必须配对使用**（MuMain 的网络层直接内嵌了 `MUnique.OpenMU.Network`）。
- MuMain 已实现：帧率提升（默认 VSync 无上限；无 VSync 时限制到显示器刷新率）、渲染重写为 SDL GPU 延迟命令、UTF-16 全 Unicode 化、库存/仓库扩展、S6 大师技能树、MU Helper（挂机）UI 与逻辑、自动重连、Inventory/Vault 扩展、新增若干分辨率。

### 1.2 游戏资源从哪里来（你问的"资源仓库"）

用户原仓库"资源不全"的疑惑，答案如下：

1. **客户端运行时（引擎）**：MuMain 的 GitHub Releases 提供三平台"无数据运行时"压缩包：
   - `MuMain-windows-native-x64-release-editor-off-no-data.tar.gz`
   - `MuMain-linux-native-x64-release-editor-off-no-data.tar.gz`
   - `MuMain-macos-native-arm64-release-editor-off-no-data.tar.gz`
2. **游戏资源（素材）**：同一 Releases 页有独立的数据发布，标签形如 `data-<id>`，当前最新为 **`data-7fce146eb3fe34a0`**（2026-09-02 发布，约 447MB，含 `Data/` 与 `fonts/`，附 `.sha256` 校验文件）。每个客户端 Release 说明里都有"Compatible game data"链接，指向与其配对的数据版本。
3. 数据本体也在仓库内：`src/bin/Data/` 与 `src/bin/fonts/`（数据工作流按内容哈希生成 `data-<id>`，数据没变就不重复发布）。
4. 组装方法（官方标准流程，`docs/build/README.md` "Assemble a release" 一节）：
   ```bash
   mkdir MuMain-runtime
   tar -xzf MuMain-<os>-...-no-data.tar.gz -C MuMain-runtime
   sha256sum --check MuMain-data-<id>.tar.gz.sha256
   tar -xzf MuMain-data-<id>.tar.gz -C MuMain-runtime
   # macOS：数据需放入 Main.app/Contents/MacOS 内
   ```
5. 备选路线：OpenMU 也兼容**原版 Webzen 客户端**（连接端口 44405 与 MuMain 的 44406 分开），官方提供 `MUnique.OpenMU.ClientLauncher`（v0.9.6）用于启动原版客户端。但原版客户端是 Windows/DirectX 老程序，无法跨平台、难改造，**本项目一律以 MuMain 为唯一客户端路线**。

**⚠️ 法律提示**：游戏素材版权归 Webzen 所有。本项目定位为你个人学习/研究/自娱用途，不得公开再分发素材包、不得商用。执行 AI 在产出物中不得内嵌或转发素材下载链接，只引用上游官方入口。

### 1.4 服务端架构要点（影响 M3/M5）

- 子系统：connect server / game server(s) / chat server / login server / admin panel，可 all-in-one 单进程，也可分布式（**官方文档明确标注 distributed 目前损坏不受支持，勿选**）。
- 数据持久化：EF Core + PostgreSQL；**全部游戏配置（数值）存数据库**，启动时加载，改动后在管理面板 "Reload configuration and restart all game servers" 生效。
- 插件化：消息处理（`IPacketHandlerPlugIn`）与视图（`IViewPlugIn`）皆为插件，可在管理面板启停——理论上服务端也能扩展手柄相关协议，但本计划的手柄方案**纯客户端实现，不动协议**，风险最小。
- 管理面板（GM 系统）：ASP.NET Core Blazor Server，内嵌 Kestrel，**浏览器访问 = 天然全平台**。页面含：Setup / Servers / Accounts / Online accounts / Game configuration（数值总入口）/ Plugins / Chat commands / Map editor / Live map / Logs / Users / API keys。
- 多语言：面板文本来自 .resx 资源文件，官方说明"其他语言以卫星资源文件(satellite resource files)加入后自动出现在语言选择器"。

## 2. 基线能力盘点（避免重复造轮子）

**客户端 MuMain 已有：**
- 帧率：`GetFPSLimit()` 读取显示器当前刷新率作为上限；`SetTargetFps(double)` 支持 30/60/144/-1(无上限) 任意值；聊天命令 `$fps <value>`、`$vsync on|off`、`$fpscounter on|off`、`$details on|off`（性能覆盖层）、`$glstats on|off`。
- 游戏逻辑与帧率解耦：ADR-0001《Preserve 25 FPS Reference Timing》——`REFERENCE_FPS=25`，`FPS_ANIMATION_FACTOR = clamp(25/FPS, 0, 1)` 乘以所有逐帧动画/移动/物理增量，指数型变化用 `pow(base, factor)`。**高刷新率不会导致游戏加速**，这是 M1 可行性的根本保障。
- 分辨率：选项界面已有分辨率下拉（枚举 `SDL_GetFullscreenDisplayModes`，排序去重、就近匹配），`MuApplyWindowResolution(w,h,windowed)` 运行时切换（窗口化 `SDL_SetWindowSize`；全屏 `SDL_GetClosestFullscreenDisplayMode` 选最接近的真实模式，否则回退无边框桌面模式）。
- 翻译系统：`.resx → ResxGen(tools/ResxGen, .NET) → Generated/I18N/*.h|cpp`；现有语言组 `Game / Dialog / Metadata / Editor`，已有 locale：en、de、es、id、ja、pl、pt、ru、tl、uk、**zh-TW**；运行时可切换（选项界面语言下拉 → `I18N::SetLocale` → 持久化 `GameConfig.UILocale`），缺键回退英文。
- 跨平台构建：Windows x64/x86、Linux x64、macOS arm64 官方 CI 产物；CMake presets；`ENABLE_EDITOR` 开关内置 ImGui 编辑器（F12，可做 bmd 等数据编辑工具）。
- 网络：内嵌 `MUnique.OpenMU.Network`，C# 客户端库 Native AOT（`MUnique.Client.Library.so/.dll` 放在可执行文件旁，运行时 dlopen/LoadLibrary）。
- 输入现状：SDL3 事件循环（`SDLEventLoop.cpp`）只处理键盘/鼠标/滚轮/文本输入；`CInput`（Core/Input/Input.h）+ `KeyState`（VK 码↔SDL scancode 映射）；**没有任何 SDL_Gamepad 代码**（全仓库仅 `SDL_GameController` 零命中）。

**服务端 OpenMU 已有：**
- Docker 一键：`deploy/all-in-one`（docker-compose：OpenMU + PostgreSQL + nginx），镜像 `munique/openmu`；另有 Traefik 变体。
- GM 命令（聊天命令插件，管理面板可启停/配置权限）：`/move`、`/setlevel`、`/setmoney`、`/addstat`（及 `/addstr` 等分项）、`/item`（发物品）、`/skin`、`/pkclear`、`/setresets`、`/getlevel`、`/getmoney`、`/charinfo`、`/createmonster`、`/movemonster`、`/ban*`、`/hide`、`/unhide`、`/disconnect`、`/guildmove`、`/guildwar`、`/changlanguage`（游戏内切换数据语言）、`/help`、`/list` 等，外加 Reset 系列（`/reset`、`/resetstats`、`/resetinfo`）。
- 数值模型：`GameConfiguration`（全局）、`CharacterClass`、`MonsterDefinition`、`ItemDefinition`、`Skill`、`DropItemGroup`、`WarpInfo`、`MiniGameDefinition`、`MerchantStore`、`ItemCrafting`（混沌机器）、`JewelMix`、`CastleSiegeConfiguration`、`DuelConfiguration` 等，全部可在管理面板编辑。

## 3. 模块 M1：帧率与分辨率（客户端）

### 3.1 需求重述

- 帧率档位：30 / 60 / 90 / 120 / 144 / 180 / 显示器刷新率上限 / 无限制，可在游戏内选项界面随时切换并持久化。
- 分辨率：支持显示器全部可用模式（含窗口化、全屏、无边框），可自由切换并持久化。
- 切换后游戏逻辑速度不得改变（已由 ADR-0001 保证，但需测试验证）。

### 3.2 现状机制（源码事实）

| `SetTargetFps(double)` / `GetTargetFps()`：`-1` = 无上限 | `src/source/Scenes/SceneManager.cpp` 第 198–211 行、`SceneManager.h` |
| VSync 偏好持久化：`MuSetVSyncPreference(bool)` → `GameConfig::SetVSyncEnabled` + `Save()`，延迟到渲染上下文应用（`ApplyVSyncPreferenceNow`：VSync 不可用时 `SetTargetFps(GetFPSLimit())`；开启时 `SetTargetFps(-1)`） | 同上 Winmain.cpp 第 289–320 行附近 |
| 配置键：`[Render] VSync`（默认 true）；`[Window] Width/Height/Windowed` | `src/source/Data/GameConfig/GameConfigConstants.h`（`CfgKeyVSync` 第 48 行、`CfgDefaultVSync` 第 84 行）、`GameConfig.cpp` 第 85/129 行、`src/bin/config.ini.template` |
| `$fps` 命令落点 | `src/source/Core/Utilities/Log/muConsoleDebug.cpp` 第 123 行（`SetTargetFps`）；命令注册见 `src/source/GameLogic/Commands/ChatCommandCatalog.cpp` |
| 帧率相关的活动窗口降帧 | `SDLEventLoop.cpp`（`g_TargetFpsBeforeInactive` / `INACTIVE_REFERENCE_FPS`） |

### 3.3 改动清单（M1）

3. `config.ini.template` 增加 `FpsPreset=0` 注释示例。

**任务 M1-T2：选项界面帧率下拉**
1. 在 `NewUIOptionWindow.cpp` 仿照现有分辨率/语言下拉（`CNewUIComboBox`）新增"帧率"下拉，固定选项：`30 / 60 / 90 / 120 / 144 / 180 / 显示器上限(<当前值>Hz) / 无限制`。显示器上限值用 `GetFPSLimit()` 实时读取并显示在文本中（如"显示器上限 (144Hz)"）。

**任务 M1-T4：启动流程与恢复**
1. 启动时按 `FpsPreset` 恢复（在现有 `ApplyPendingVSyncPreference` 之后，初始化渲染上下文处）。

**任务 M1-T5：验证**

- 超宽屏/4K/窗口化拖拽：UI 无错位（基准分辨率缩放机制）。

### 4.2 客户端 A 层：resx 汉化（详细步骤）

1. 复制翻译基线：以 `src/Localization/Game.zh-TW.resx`、`Dialog.*`（zh-TW 无 Dialog 则从 en 翻）等为基础，生成：
   - `src/Localization/Game.zh-CN.resx`
   - `src/Localization/Dialog.zh-CN.resx`
   - `src/Localization/Metadata.zh-CN.resx`
   - `src/Localization/Editor.zh-CN.resx`（Editor 组仅编辑器构建使用，可最低优先级）
   - 规则：`<data name="...">` 的 key 必须与 en 完全一致，只改 `<value>`；带 `<comment>legacy_id=N</comment>` 的条目**必须保留 comment**（旧 `GlobalText[N]` 按索引查找依赖它）；占位符 `{0}/{1}` 与宽字符 `%s/%ls` 原样保留。

## 6. 模块 M4：全手柄支持 + 多模式震动（最重模块）

### 6.1 需求拆解

1. **全功能覆盖**：从启动器之后的所有界面——角色选择/创建、主城移动战斗、背包装备、商店、混沌机器、仓库、交易、队伍、公会、信使、信件、传送、小地图/世界地图、任务、大师技能树、MU Helper、聊天、选项、活动入场、决斗——全部可手柄完成，"所有地方都不要漏"。
2. **震动**：短震、长震、不同力度；按游戏事件触发（受击、暴击、掉宝、升级、死亡、低血心跳等），可配置。

### 6.2 现状与约束（源码事实）

- 输入栈：`SDLEventLoop.cpp`（SDL3 事件 → 老式全局量：`MouseWheel`、`g_szSDLTextInput`、`Core::Input::RecordLeftMouseButtonPressEdge()` 等）→ `CInput`（鼠标状态机 + `SEASON3B::IsPress/IsRepeat` 键盘 VK 查询）→ 各场景/窗口消费。**无 SDL_Gamepad 代码**（全仓库检索仅 0 处）。
- 键盘映射：`KeyState.cpp` 做 VK↔SDL scancode 映射——说明存在"虚拟按键注入"的天然层：手柄按键可以注入为 VK 事件复用所有键盘逻辑。
- 移动：点击寻路（点地面生成路径发送服务器）；方向键移动仅存在于编辑器相机模式（`DefaultCamera::HandleEditorMode`，非正式玩法）。
- 战斗：`ClassAttack.cpp` 有 `CheckAttack()`/`SelectedCharacter` 目标判定；`SkillCast.cpp`/`SkillExecution.cpp` 有施法链路；**MuMain 已内置 MU Helper（自动战斗）逻辑**——可复用它做"最近目标选择/自动索敌"。
- UI：大量窗口类在 `src/source/UI/NewUI/`（含 `Widgets/`、`Inventory/`、`Options/`、`Chat/` 等）+ `UI/Legacy/UIControls.cpp`（方向键列表选择已有先例，第 794–813、3150 行附近）——说明"列表键盘导航"已部分存在，网格导航没有。
- SDL3 提供完整手柄能力：`SDL_EVENT_GAMEPAD_ADDED/REMOVED/REMAPPED`、`SDL_OpenGamepad`、`SDL_GetGamepads`、按键/摇杆/陀螺仪状态、**`SDL_RumbleGamepad(g, low_freq, high_freq, duration_ms)`**、`SDL_SetGamepadTriggerEffect`（自适应扳机，DualSense）、`SDL_GamepadMappings` 数据库（Xbox/PS/Switch 手柄免驱免配置）。
- 平台注意：macOS 蓝牙手柄、Linux 的 evdev/steam 输入权限（uinput/udev 规则文档要写）、Windows 原生支持。

### 6.3 总体架构（新增目录 `src/source/Core/Input/Gamepad/`）

```
GamepadManager      手柄生命周期：枚举/热插拔/映射/多柄选择"活动手柄"，每帧采样
GamepadState        标准化状态快照：按键集、双摇杆、扳机、陀螺仪(可选)
GamepadBindings     绑定表：按"上下文"分组的 按键→动作 映射；可重绑定；持久化 config.ini [Gamepad]
VirtualCursor       虚拟光标：右摇杆(或左)→屏幕坐标，加速曲线，边缘钳制，可吸附最近可交互元素
GameActionAdapter   动作层：把抽象动作翻译成既有游戏调用（点击地面/点怪物/按键注入/窗口方法直调）
UIFocusSystem       UI 焦点导航：窗口级焦点图（列表/网格/按钮），方向键在焦点间移动，A 确认 B 返回

```

### 6.4 双模式输入设计（全功能覆盖的关键）

**模式 A：虚拟光标模式（覆盖 100% 功能，兜底）**
- 右摇杆移动虚拟光标（速度曲线：小幅度精细、大幅度加速），A=左键、B=右键、X=左键双击（快速拾取/穿戴）、Y=上下文动作（对话/打开）。
- 所有现有鼠标操作天然可用：背包拖拽、商店买卖、地图点击、聊天点人。
- 吸附辅助：光标接近可点击元素（按钮/格子/怪物）时轻微吸附 + 高亮。

**模式 B：直接动作模式（ gameplay 时的最佳手感，叠加在 A 之上）**
- 左摇杆=直接移动：按摇杆方向每 100–150ms 对目标方向做一次寻路并发送路径（复用点击寻路的同一寻路算法与发包路径——实现时先定位点击移动的寻路调用点，将其参数化：输入=世界坐标点；摇杆模式输入=英雄位置+方向×距离）。死区 0.25，八方向量化（MU 是斜 45°网格寻路）。
- 攻击键（默认 RB 或 A）：锁定"最近可攻击目标"（复用 MU Helper 索敌/`SelectedCharacter` 逻辑），按下即走向并攻击；按住连击。
- 技能 1–8（默认 肩键+面板键组合或右摇杆按下方向）：读当前装配技能槽依次映射。
- 药水快捷键（默认 十字键：上=红药、左=蓝药、下=召唤/辅助、右=增益）：调用现有喝药逻辑。
- 拾取：靠近掉落物按 X。
- 进入任何窗口（背包/技能/地图…）后自动切到模式 A 的焦点导航，关闭窗口回到模式 B。

### 6.6 震动系统（RumbleManager）

**API 语义**：`SDL_RumbleGamepad(gamepad, low_frequency, high_frequency, duration_ms)`，频率 0–65535；低频率=左侧大马达（沉闷、"重"），高频率=右侧小马达（尖锐、"刺"）；时长到自动停；循环效果用定时器重触发实现。扳机马达 `SDL_SetGamepadTriggerEffect`（可选 P3 阶段，仅 DualSense/部分 Xbox）。

**事件表（初始默认值，全部可在设置中开关/调强度）**：

| 游戏事件 | 低/高频率 | 时长 | 形态 | 触发点（客户端挂钩建议） |
|---|---|---|---|---|
| 受到普通攻击 | 12000/20000 | 120ms | 短震，强度随伤害/最大HP 比例缩放 | 伤害消息处理（角色受伤视图消息） |
| 受到暴击/重击 | 30000/40000 | 200ms | 短强震 | 同上（暴击标志） |
| 自己打出暴击 | 0/25000 | 80ms | 轻刺 | 伤害输出消息（暴击标志） |
| 击杀怪物 | 15000/15000 | 100ms | 中震 | 目标死亡消息 |
| 升级 | 双脉冲 25000/35000 | 150ms×2 间隔 120ms | 两连脉冲 | 升级消息/特效点 |
| 掉落卓越/套装物品 | 20000/45000 | 250ms | 强震+尾刺 | 物品拾取消息（稀有度判定） |
| 宝石强化成功 | 0/35000 | 100ms | 轻刺 | 强化结果消息 |
| 强化失败 | 40000/0 | 350ms | 长闷震 | 同上 |
| 混沌机器合成成功 | 双脉冲 20000/30000 | 150ms×2 | 两连脉冲 | 合成结果消息 |
| 混沌机器合成失败 | 50000/10000 | 500ms | 长重震 | 同上 |
| 角色死亡 | 60000/20000 | 700ms | 长重震 | 死亡状态消息 |
| 低血量(<20%) | 18000/0 | 120ms 每 1.5s | 心跳循环（直到回血>30%） | HP 变化检查 |
| 施放技能 | 按技能类别 3 档 | 60–150ms | 轻/中/重 | 施法视图消息（可按技能 ID 配置） |
| 骑乘/召唤坐骑 | 25000/10000 | 200ms | 中震 | 骑乘状态消息 |
| 活动开始倒计时 | 三连轻脉冲 | 80ms×3 | 提示 | 活动事件消息 |
| 交易完成 | 双脉冲 15000/25000 | 120ms×2 | 确认感 | 交易成功消息 |
| 被 GM 踢下线/断线重连 | 40000/40000 | 400ms | 长震 | 连接状态消息 |

**配置项**（`config.ini [Gamepad]` + 选项 UI）：`RumbleEnabled=1`、`RumbleIntensity=100`（0–200%，乘到频率上）、`RumbleCombat=1`、`RumbleLoot=1`、`RumbleSystem=1`（三组总开关）、每事件高级开关（可延后）。所有事件带冷却（同类最小间隔 80ms）防止刷屏。

### 6.7 实施分期（给执行 AI 的顺序）

- **P1 基础层（先跑通）**：GamepadManager + 手柄识别/热插拔；VirtualCursor + A/B 点击；能用手柄完成"登录→选角→进入游戏→走路→攻击→捡东西"。

- **P3 战斗增强与震动**：直接移动寻路、技能/药水快捷键、RumbleManager 事件表全量接入。
- **P4 打磨**：死区/曲线调参、重绑定界面、扳机效果、陀螺仪体感瞄准（可选）、无障碍选项。

### 6.8 验收标准（M4）

- [ ] 从启动到退出全流程：仅用手柄可完成 6.5 清单全部 29 类界面操作（录屏逐一演示）。
- [ ] 三种主流手柄（Xbox 系列/PS5 DualSense/Switch Pro）在 Win、Linux、macOS 上即插即用、可热插拔。

## 7. 模块 M5：数值全面改造（单机向，零代码）

### 7.1 原理与操作通道（先讲清楚"怎么改"）

1. **所有数值都在服务端 PostgreSQL 数据库里**，由 `src/Persistence/Initialization/`（C# 初始化器，含 `VersionSeasonSix/` 全部物品/怪物/技能/地图/商店/任务/混沌配方）首次播种，之后**以数据库为准**。
2. **首选通道：管理面板网页编辑**（Configuration 下拉）。改完到 Servers 页点 **"Reload configuration and restart all game servers"** 生效（官方警告：不重启不生效）。
3. **改前必备份**：`pg_dump`（容器内）或面板自带备份服务；一次只改一类，改完立刻进游戏验证。
4. 通用编辑页有两种：`edit-config-grid/{类型}`（表格，支持搜索/排序/复制行/删除）与 `edit-config/{类型}/{id}`（表单）。**导航搜索框**可按名字直达对象（比翻树快）。
5. 官方提醒（原文意译）：通用编辑页是数据模型的直接视图，不懂游戏规则也可能配出无效组合——**一次改一项、改完测试、大改前备份**。

### 7.2 数值层级与入口（对照管理面板页面）

| 层级 | 面板位置 | 关键字段（已核对源码） |
|---|---|---|
| 全局 | Configuration → Game configuration（General 页，`edit-config/…GameConfiguration/{id}/hide-collections`） | `ExperienceRate`、`MasterExperienceRate`、`ExperienceFormula`、`MasterExperienceFormula`（**数学表达式字符串，可直接改**）、`MaximumLevel`、`MaximumMasterLevel`、`MinimumMonsterLevelForMasterExperience`、`MaximumInventoryMoney`、`MaximumVaultMoney`、`ShouldDropMoney`、`ItemDropDuration`、`MaximumItemOptionLevelDrop`、`ExcellentItemDropLevelDelta`、`MaximumCharactersPerAccount`、`MaximumPartySize`、`RecoveryInterval`、耐久消耗系数 |
| 职业 | Character classes（`CharacterClass`） | `StatAttributes`（每级加点成长）、`BaseAttributeValues`（基础属性）、`LevelRequirementByCreation`、`HomeMap`、转职链 `NextGenerationClass`、`FruitCalculation` |
| 怪物 | Monsters（`MonsterDefinition`） | `Attributes`（HP/伤害/防御/攻速等全部战斗属性）、`MoveRange/AttackRange/ViewRange`、`MoveDelay/AttackDelay/RespawnDelay`、`NumberOfMaximumItemDrops`、掉落组、AI |
| 物品 | Items（`ItemDefinition`，专用图形编辑器） | 基础攻击/防御/速度、`LevelBonusTable`（+0~+15 成长）、需求、可选项、插槽、职业限制 |
| 技能 | Skills（`Skill`） | 伤害、MP/AG 消耗、距离、目标限制、大师技能树依赖 |
| 掉落 | Drop item groups（`DropItemGroup`） | 概率 0–1、可挂全局/地图/怪物；**注意：组按顺序评估、金币组常为兜底，调高一组=压低其余** |
| 商店 | Merchant stores（图形化商店编辑器） | NPC 售卖清单 |
| 传送 | Warp list（`WarpInfo`） | 费用、等级要求 |
| 活动 | Mini games（`MiniGameDefinition`） | 入场、刷怪波次、奖励、时间表（时区在 System 页设） |
| 混沌机器 | Item craftings（在完整配置树内） | 各配方成功率 |
| 宝石堆叠 | Jewel mixes | 合成/拆分 |
| 插件 | Plugins 页 | Reset 系统、随机经验、全局金币倍率等可配置插件 |
| 聊天命令 | Chat commands 页 | 每条命令的启用/权限/参数配置 |

### 7.3 "单人舒适向"推荐数值档（起始建议值，可自行再调）

> 定位：你一个人玩、不想氪、想要"变强有节奏但不受苦"。以下为**建议起始值**，不是官方数据。

**全局（General 页）**

| 项 | 默认参考 | 建议值 | 理由 |
|---|---|---|---|
| ExperienceRate | 1 | **10–30** | 单人快速过前期；50 以上容易秒升失去节奏 |
| MasterExperienceRate | 1 | **10–20** | 大师等级阶段同理 |
| ExperienceFormula | S6 原版分段公式 | 保持原版 | 曲线本身合理；倍率已够快，不必改公式 |
| MaximumLevel / MasterLevel | 400 / 200 | 保持 | 内容完整 |
| MaximumInventoryMoney / VaultMoney | 原版上限 | 调到 2,000,000,000 级 | 单机不缺仓库 |
| ItemDropDuration | 原版 | 60s→**120s** | 捡东西不着急 |
| ExcellentItemDropLevelDelta | 原版 | **+2~+4** | 卓越装更早可得 |
| ShouldDropMoney | 是 | 保持 | 金币手感 |

**职业（CharacterClass → StatAttributes）**
- 每级属性点：原版每级少量（按职业不同）→ 建议 **每级 10–15 点**，体验"自由加点"；想更爽可 20+，但会稀释加点策略性。
- 同时把 `BaseAttributeValues` 里的初始血量略提（避免 1 级被秒）。

**怪物（MonsterDefinition.Attributes）**
- 普通图（Lorencia/Devias/Dungeon/Atlans 等）：HP ×0.5–0.6、伤害 ×0.6–0.7、防御 ×0.7；
- 中后期图（LostTower/Tarkan/Aida/Icarus 等）：HP ×0.7、伤害 ×0.8；
- BOSS/精英（如 Kundun 系）：保持或 ×0.9，留挑战；
- `AttackDelay` 可 +20%（出手更慢更从容），`RespawnDelay` 缩短 30%（怪刷得快，不缺经验包）。
- 操作技巧：用表格页按地图筛怪 → 逐只改太累时，优先改"该地图刷怪密度高、你主要练级的 3–5 种怪"。

**掉落（DropItemGroup）**
- 提升卓越组/套装组概率 2–3 倍；
- 给常用练级怪挂"治疗药水/魔力药水"掉落组（概率 0.05–0.1）；
- 宝石（Bless/Soul/Chaos/Life/Creation）掉落组概率 ×2–3；
- 记得文档提示：概率按序消耗，改一组要看总量。

**商店（Merchant stores）**
- 在 Lorencia 新手商店补齐：所有基础药水、箭矢/弹丸、传送卷轴、小翅膀材料；
- 设置一个"单人补给"NPC：直接售卖 Bless/Soul 宝石（单价适中），替代原版的氪金获取路径。

**传送（WarpInfo）**：全部费用降到 0–2000 金币，等级要求按地图最低走——单人跑图时间全花在战斗上。

**混沌机器**：普通合成成功率 **+15–20%**，翅膀/套装类高价值配方 +10%；失败不掉装备的选项若可配则开启（以面板实际字段为准）。

**插件**：启用 Reset 插件（面板 Plugins + 命令 `/reset`），设置合理的转生点数奖励，形成"练满→转生→变强"的单机循环。

### 7.4 GM 命令自用清单（账号设为 GameMaster 后可用，均为服务端已内置插件）

`/move <地图>` 传送、`/setlevel <等级>`、`/setmasterlevel`（以命令帮助为准）、`/setmoney <数额>`、`/addstr|/addagi|/addvit|/addene|/addcmd <数值>` 或通用 `/addstat`、`/item <参数>` 直接生成物品、`/skin` 变外观、`/pkclear` 清 PK、`/setresets`、`/getlevel /getmoney /getstat /charinfo` 查询、`/createmonster /movemonster`、`/hide /unhide` 隐身 GM、`/disconnect <角色>`、`/guildmove /guildwar`、`/changelanguage`（游戏内切数据语言，M2 验证用）、`/help`、`/list`。
> 参数与权限以面板 Chat commands 页为准（可按 GameMaster 过滤导出完整清单）。

## 9. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 素材版权（Webzen） | 高 | 仅个人用途；不分发素材包；发行包只给"引擎 + 你自己的改动"，数据由用户自行从上游获取 |

| `data-<id>` 与运行时版本错配 | 中 | 严格按 Release 说明的 Compatible game data 链接配对；更新脚本做校验 |
| macOS 仅 arm64 官方产物 | 低 | Intel Mac 本地构建（文档已有平台指南） |
| 分布式部署损坏（官方标注） | — | 不使用，all-in-one 足够 |
| 手柄适配窗口遗漏 | 中 | 以 6.5 清单逐项打勾验收；录屏留档 |
| bmd 格式工具链不熟 | 中 | 优先用官方 MuEditor（F12）；先拿一个文件跑通 导出→改→导入→游戏验证 全流程再批量 |

| 面板公网暴露安全事故 | 高 | 严格执行 5.2 第 3 条三步（建用户/HTTPS/防火墙） |
| 数值改坏（无效组合） | 中 | 一次一类 + 备份 + 面板通用编辑页官方警告遵守 |
