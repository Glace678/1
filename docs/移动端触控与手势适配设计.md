# 移动端（Android / iOS）触控与手势适配设计

> 状态：设计文档（v1，2026-09-05）。移动端**尚不可构建**——上游与本仓库的
> `docs/build/android/README.md`、`docs/build/iOS/README.md` 均明确标注
> "planned / not yet a supported build target"。本文给出从当前桌面架构到移动端
> 的最短路径，供后续执行 AI 按图施工。

## 1. 现状盘点（可复用的基础）

| 已有能力 | 位置 | 对移动端的意义 |
|---|---|---|
| SDL3 平台层（窗口/输入/事件） | `MuMain/src/source/Core/Platform/` | SDL3 官方支持 Android/iOS，事件循环可平移 |
| SDL GPU 渲染（Metal/Vulkan/D3D12） | `Render/Renderer/MuRendererSDLGpu.cpp` | iOS 走 Metal、Android 走 Vulkan/GLES，SDL GPU 已抽象 |
| 语义输入层 GamepadService | `Core/Input/GamepadService.h` | **`OnPhysicalPointerInput(x,y)` / `SetPointerPosition` 已经是"指针注入"接口**——触控即指针，天然复用 |
| 输入所有权切换 | `ConsumeInputOwnershipChanged()` | 触屏/手柄/键鼠互切已有机制 |
| 震动系统 Haptics（分类/事件/脉冲模式/调度器） | `Core/Haptics/Haptics.h` | iOS 可接 Core Haptics、Android 接 VibrationEffect，实现 `IHapticOutput` 即可 |
| 帧率策略（跟随显示器/固定档/后台降频） | `[Render] FrameRateMode` + FrameClock | 手机 90/120Hz 屏与省电 30/60 档直接适用 |
| UI 参考分辨率缩放 | `App/stdafx.h`（reference resolution） | 手机异形屏适配的缩放基础 |
| Rime 中文输入（Linux/macOS） | `src/third_party/librime` + `Core/Input/ImeInput` | 移动端改用系统 IME（SDL3 有 screen keyboard 支持） |

## 2. 触控输入设计（TouchService）

新建 `Core/Input/Touch/`，镜像 GamepadService 的结构：

```
TouchService        SDL_EVENT_FINGERDOWN/UP/MOTION 消费；多指追踪（最多 5 指）
GestureRecognizer   手势识别：单击/双击/长按/拖拽/双指滑动/三指滑动/双指缩放/边缘滑动
VirtualStick        左半屏虚拟摇杆（移动），带死区与归中动画
ScreenButtons       右半屏浮动按钮层（攻击/技能 1-4/药水/拾取/菜单），可编辑布局
TouchSettings       灵敏度、按键透明度、左右手模式、摇杆固定/浮动，持久化 config
```

**关键决策：不做"触控→鼠标合成"凑合方案**。SDL3 默认会把单指触控合成为鼠标事件
（`SDL_HINT_TOUCH_MOUSE_EVENTS`），这能让游戏"能点"，但无法实现双指/三指手势与
分区操作。正确做法：关闭触控鼠标合成，由 TouchService 统一消费手指事件，再调用
既有 `GamepadService::OnPhysicalPointerInput` / 语义动作层分发——与手柄共用同一套
"语义输入→游戏动作"管线，所有 85 个界面（见 `docs/controller-coverage.csv`）
零改动获得触控支持。

**分区操作**（用户要求的左右分区）：
- 左半屏下半区 = 虚拟摇杆（按下即出现，浮动式）；
- 右半屏 = 动作按钮层（攻击大钮 + 技能弧形排布 + 药水小钮）；
- 上半屏中央 = 状态条只读区（不响应误触）；
- 任何 UI 窗口打开时：整屏切换为"指针模式"（单指=光标，见第 2 节），分区隐藏。

## 4. 屏幕比例与安全区

1. **画面占比策略**（设置项 `ScreenFit`）：
   - `Fit`（默认）：保持 4:3/16:9 内容比例，两侧/上下留边（渐变黑边），UI 锚定安全区——最稳妥，不改素材；
   - `Fill`：拉满屏幕，UI 重锚定到安全区，3D 视野按宽高比扩展（桌面端已有 wider-resolution 扩展视野机制，见 `Camera/CameraConfig.h`）。
2. **刘海/圆角安全区**：SDL3 `SDL_GetWindowBordersSize` + 平台 safe-area insets（iOS `safeAreaInsets`、Android `WindowInsets`），HUD 元素（血条、小地图、聊天）向内收缩。
3. **UI 缩放**：沿用参考分辨率体系，按短边比例缩放；按钮触控热区最小 44×44pt（Apple HIG）/48×48dp（Material），视觉尺寸不变、热区放大。
4. **横屏锁定**：游戏仅横屏；iOS 支持 `UIRequiresFullScreen` + 灵动岛避让。

## 5. 移动端震动

实现 `IHapticOutput` 两个子类：
- iOS：Core Haptics（`CHHapticEngine`），连续+瞬态混合，支持强度/锐度包络——`HapticPattern` 的多脉冲序列可直译；旧设备回退 `UIImpactFeedbackGenerator`。
- Android：`VibratorManager` + `VibrationEffect.Composition`（API 31+ 分段振幅；以下回退 `waveform` 数组）。
- 事件表复用桌面 `HapticEvent` 全集（受击/暴击/击杀/升级/掉落/合成/死亡/低血心跳），移动端默认强度 60%（省电+马达差异）。
